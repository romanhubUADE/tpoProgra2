Programación II — TP 07

Sistema de Login con TDA Dictionary

Implementación del Tipo de Dato Abstracto Dictionary en Java · Con bonus de bloqueo de cuenta

¿Qué pide el TP?

El TP 07 tiene dos partes concretas:

① Implementar el TDA Dictionary

Construir la interfaz y su implementación desde cero — sin usar HashMap ni colecciones de Java. El TDA debe lanzar excepciones ante datos inválidos.

② Aplicación de consola en Java

Elegir entre Sistema de Login o Sistema de Inventario. Se eligió el Login. El TDA Dictionary es la estructura de datos subyacente.

Requisitos del Sistema de Login

  • Registrar usuarios con nombre único y contraseña.
  • Iniciar sesión verificando que la contraseña coincida.
  • Manejar todos los inputs inválidos del usuario sin crashear.
  • Bonus: bloquear la cuenta al tercer intento fallido. El bloqueo persiste aunque el usuario vuelva al menú principal.
Regla clave del enunciado: las implementaciones del TDA deben lanzar excepciones ante comandos inválidos. Es la aplicación la que debe garantizar que eso nunca ocurra — validando antes de llamar.

Qué hace cada archivo

Interface tda/Dictionary.java

Define el contrato del TDA. Declara las operaciones que cualquier implementación debe proveer, sin decir cómo.

MétodoDescripción
put(key, value)Inserta un par. Lanza DuplicateKeyException si la clave ya existe.
get(key)Devuelve el valor. Lanza KeyNotFoundException si no existe.
update(key, value)Actualiza el valor. Lanza KeyNotFoundException si no existe.
remove(key)Elimina el par. Lanza KeyNotFoundException si no existe.
containsKey(key)Devuelve true/false sin lanzar excepciones.
isEmpty()Indica si el diccionario está vacío.
size()Cantidad de pares almacenados.

Impl tda/LinkedDictionary.java

Implementación del Dictionary usando una lista enlazada simple. No usa ninguna colección de Java — construye sus propios nodos (Entry<K,V> como clase interna privada).

Cada nodo guarda: clave, valor, y puntero al siguiente nodo. Los nuevos elementos se insertan al frente de la lista (O(1)). Las búsquedas recorren secuencialmente (O(n)). 

// Nodo interno (clase privada dentro de LinkedDictionary)
private static class Entry<K, V> {
    K key;
    V value;
    Entry<K, V> next;
}
¿Por qué lista enlazada y no array? El tamaño del diccionario no se conoce de antemano. La lista enlazada crece dinámicamente sin desperdiciar memoria. Un array requeriría redimensionamiento manual.

Exception exception/DuplicateKeyException.java & KeyNotFoundException.java

Excepciones checked propias del TDA. Al ser checked, Java obliga al código cliente a manejarlas (o declararlas), lo que hace el contrato explícito en tiempo de compilación.

Model model/User.java

Representa a un usuario del sistema. Almacena usuario, contraseña y el estado de seguridad: contador de intentos fallidos y si la cuenta está bloqueada.

La lógica de bloqueo vive aquí (registerFailedAttempt()), no en el servicio ni en la UI — respetando que cada clase tenga una sola responsabilidad. 

public void registerFailedAttempt() {
    failedAttempts++;
    if (failedAttempts >= MAX_FAILED_ATTEMPTS) {
        blocked = true;   // bloqueo automático al llegar al límite
    }
}

Service service/AuthService.java

Contiene toda la lógica de negocio del sistema de login. Usa el Dictionary para guardar usuarios y define el comportamiento de registro y login como enums de resultado (en lugar de excepciones), lo que hace el flujo más limpio del lado de la UI.

Patrón clave: siempre llama a containsKey() antes de put(), get(), o update() — garantizando que el TDA nunca reciba comandos inválidos (como exige el enunciado). 

// Ejemplo: registro seguro
if (users.containsKey(username)) {
    return RegisterResult.USERNAME_ALREADY_EXISTS;  // nunca llega al put()
}
users.put(username, new User(username, password));   // seguro

UI ui/ConsoleMenu.java

Maneja toda la interacción con el usuario: imprime los menús, lee inputs y muestra resultados. No tiene lógica de negocio — sólo llama a AuthService e interpreta el resultado.

Dos métodos de lectura defensivos que nunca retornan un input inválido:

  • readMenuOption(min, max) — repite hasta obtener un entero en el rango.
  • readNonBlank(prompt) — repite hasta obtener texto no vacío.

Main Main.java

Punto de entrada. Crea el AuthService y lo inyecta en el ConsoleMenu. ConsoleMenu no construye sus propias dependencias — las recibe. Esto se llama Inversión de Dependencias.

Decisiones de diseño y por qué

¿Por qué lista enlazada y no array?

El array requiere tamaño fijo o redimensionamiento manual. La lista enlazada crece con cada nuevo usuario sin desperdiciar espacio. Para la escala de este TP (pocos usuarios en memoria), es la opción más simple y correcta.

¿Por qué enums de resultado en AuthService en lugar de excepciones?

Las excepciones son para situaciones excepcionales. Escribir una contraseña incorrecta es un flujo esperado. Los enums (LoginResult.WRONG_PASSWORD) hacen el switch en la UI más legible y explícito que un try-catch anidado.

¿Por qué el bloqueo vive en User y no en AuthService?

Principio de Responsabilidad Única: User sabe sus propios datos y estado. Si mañana cambia la lógica de bloqueo (por ejemplo, desbloquear después de N horas), sólo cambia User, no el servicio.

¿Por qué ConsoleMenu recibe AuthService en el constructor?

Inversión de Dependencias: ConsoleMenu no crea sus propias dependencias. Esto facilita el testing y el reemplazo de implementaciones. Main.java es el único lugar donde se ensamblan las piezas.

¿Por qué siempre containsKey() antes de put()/get()/update()?

El enunciado lo exige explícitamente: el TDA lanza excepciones ante datos inválidos, y es la aplicación la que debe evitar que eso ocurra. containsKey() es la guardia que garantiza que las operaciones del TDA siempre reciban entradas válidas.

Cómo compilar y ejecutar

Desde la carpeta TPO7/src/:

# Compilar todos los archivos java
javac -d . tda/*.java exception/*.java model/*.java service/*.java ui/*.java Main.java

# Ejecutar
java Main
El flag -d . le dice al compilador que genere la estructura de paquetes en el directorio actual, que es lo que necesita Java para encontrar las clases por paquete.
