Que es un TDA (Tipo de Dato Abstracto)

Un TDA define que operaciones puede hacer una estructura, sin decir como las hace por dentro. Es como un contrato: "yo te prometo que vas a poder agregar, sacar y buscar elementos" — pero la implementacion interna queda oculta.

Analogia

Pensa en un control remoto. Vos sabes que tiene botones para subir el volumen, cambiar canal, apagar. Eso es la interfaz. No te importa si adentro tiene transistores o chips modernos — eso es la implementacion. El TDA es exactamente eso.

Interfaz vs Implementacion en Java

En Java, el contrato del TDA se escribe como una interface. Despues se crean una o mas clases que implementan ese contrato (implements).

// El CONTRATO (TDA)
public interface SimpleList<E> {
    boolean add(E element);
    E get(int index);
    int size();
    // ...
}

// IMPLEMENTACION 1: usando un arreglo interno
public class SimpleArrayList<E> implements SimpleList<E> { ... }

// IMPLEMENTACION 2: usando nodos enlazados
public class SimpleLinkedList<E> implements SimpleList<E> { ... }
El poder del polimorfismo

Como ambas implementan la misma interfaz, el codigo que las usa puede declarar SimpleList<String> lista = new SimpleArrayList<>(); y en cualquier momento cambiar a = new SimpleLinkedList<>(); sin tocar ningun otro codigo. Eso es polimorfismo en accion.

Patrones clave del proyecto

1. Interfaz como tipo de variable

En todos los ejercicios, la lista/pila/cola se declara con el tipo de la interfaz, no de la implementacion. Esto permite cambiar de implementacion en un solo lugar:

// En ListExercise.java
private SimpleList<String> list;

// En el constructor, elegis la implementacion:
list = new SimpleArrayList<>();   // con array
// list = new SimpleLinkedList<>(); // con nodos enlazados

2. Dos arreglos paralelos (Dictionary y PriorityQueue)

El SimpleArrayDictionary y el SimpleArrayPriorityQueue usan dos arreglos en sincronía. La posicion i en el arreglo de claves corresponde a la posicion i en el arreglo de valores/prioridades.

3. Patron de eliminacion O(1) en Set

En lugar de correr todos los elementos a la izquierda (O(n)), el Set simplemente pone el ultimo elemento en el lugar del eliminado:

// En SimpleArraySet.remove()
elements[index] = elements[size - 1]; // pisa el eliminado con el ultimo
elements[size - 1] = null;            // limpia la ultima posicion
size--;
// Funciona porque el Set NO garantiza orden

4. Enum como resultado de operacion

En lugar de lanzar excepciones o devolver null, el AuthService devuelve un enum con el resultado exacto. Esto hace el codigo del caller mucho mas claro:

// En AuthService.java
public enum LoginResult { SUCCESS, ACCOUNT_BLOCKED, WRONG_PASSWORD, USER_NOT_FOUND, INVALID_INPUT }

// En AuthExercise.java — el switch es limpio y exhaustivo
switch (authService.login(username, password)) {
    case SUCCESS:         // bienvenido
    case ACCOUNT_BLOCKED: // cuenta bloqueada
    case WRONG_PASSWORD:  // intentos restantes
    ...
}

List TDA

📋

Una Lista es una coleccion ordenada que permite elementos duplicados. Soporta acceso por indice, insercion en cualquier posicion y eliminacion.

Interfaz — SimpleList.java

remove(int index)Saca el elemento en esa posicion y lo devuelve
remove(Object object)Saca la primera ocurrencia de ese objeto

Comparativa de implementaciones

SimpleArrayList

  • Almacenamiento: arreglo interno de tipo generico
  • Capacidad inicial: 4 — se duplica cuando se llena
  • get/set: O(1) — acceso directo por indice
  • add al final: O(1) amortizado
  • add en medio / remove: O(n) — hay que correr elementos

SimpleLinkedList

  • Almacenamiento: nodos doblemente enlazados
  • Sin capacidad fija: crece de a un nodo
  • get/set: O(n) — hay que recorrer
  • add/remove en extremos: O(1)
  • Optimizacion: navega desde el extremo mas cercano

Detalle: resize dinamico en SimpleArrayList

private void resize() {
    E[] newArray = (E[]) new Object[elements.length * 2]; // duplica capacidad
    for (int i = 0; i < size; i++) {
        newArray[i] = elements[i]; // copia los elementos existentes
    }
    elements = newArray; // reemplaza la referencia
}
Por que duplicar y no sumar 1?

Si sumamos 1 cada vez, con n inserciones hacemos n resize, cada uno copiando mas elementos: total O(n²). Duplicando, el costo total amortizado es O(n) porque cada elemento se copia muy pocas veces en toda su vida.

SimpleLinkedStack — el tope es el ultimo nodo

private LinkedNode<E> last; // el tope de la pila

@Override
public void push(E element) {
    LinkedNode<E> newNode = new LinkedNode<>(element);
    if (!isEmpty()) {
        newNode.prev = last;  // el nuevo apunta al anterior tope
        last.next = newNode;  // el anterior tope apunta al nuevo
    }
    last = newNode; // el nuevo ES el tope ahora
    size++;
}

@Override
public E pop() {
    if (isEmpty()) throw new NoSuchElementException("Stack is empty.");
    E value = last.value;
    if (size == 1) {
        last = null;
    } else {
        last = last.prev;  // retrocede el tope
        last.next = null; // corta la referencia al nodo sacado
    }
    size--;
    return value;
}

Diferencia clave: Array vs Linked en Queue

El costo de dequeue en SimpleArrayQueue

En la implementacion con array, cada dequeue() saca el elemento de la posicion 0 y tiene que mover TODOS los elementos restantes una posicion a la izquierda. Eso es O(n). En la version con LinkedList, simplemente se avanza el puntero first al siguiente nodo: O(1).

// SimpleLinkedQueue — dequeue O(1)
@Override
public E dequeue() {
    if (isEmpty()) throw new NoSuchElementException("Queue is empty.");
    E value = first.value;
    if (size == 1) {
        first = null;
        last = null;
    } else {
        first = first.next; // avanzamos el frente — O(1)
        first.prev = null;
    }
    size--;
    return value;
}

Set (Conjunto) TDA

🔵

Un Set es como una lista pero sin duplicados y sin orden garantizado. Lo importante es si un elemento esta o no esta.

MetodoDescripcion
add(E)Agrega solo si no existe. Devuelve false si ya estaba.
remove(E)Elimina el elemento si existe
contains(E)Dice si el elemento esta
toArray()Devuelve los elementos en un arreglo
unionWith(SimpleSet)A ∪ B — todos los elementos de ambos
intersectWith(SimpleSet)A ∩ B — solo los que estan en ambos
differenceWith(SimpleSet)A - B — los de A que no estan en B

Union, Interseccion y Diferencia

Sean A = {1, 2, 3} y B = {2, 3, 4}

A.unionWith(B) = {1, 2, 3, 4} — todos los elementos (sin repetir)

A.intersectWith(B) = {2, 3} — solo los comunes

A.differenceWith(B) = {1} — los de A que no estan en B

@Override
public SimpleSet<E> unionWith(SimpleSet<E> other) {
    SimpleSet<E> result = new SimpleArraySet<>();
    for (E element : this.toArray()) result.add(element);
    for (E element : other.toArray()) result.add(element); // add ignora duplicados
    return result;
}

Priority Queue (Cola de Prioridad) Complejo

⚡

Como una cola, pero con prioridad numerica. El que tiene mayor prioridad sale primero, sin importar cuando entro. En este proyecto, numero menor = prioridad mas alta.

La cola mantiene el orden automaticamente:

→
Urgente (1)
→
Normal (3)

dequeue() → "Critico"

MetodoDescripcion

SimpleArrayPriorityQueue — insercion ordenada

Al hacer enqueue, el array mantiene los elementos ordenados de MAYOR a MENOR prioridad (numero mas bajo primero). Inserta corriendo elementos hacia la derecha hasta encontrar su lugar:

@Override
public void enqueue(E element, int priority) {
    validateSize(size + 1);

    int insertIndex = size; // por defecto, inserta al final

    // Recorre desde el final hacia el inicio buscando su posicion
    for (int i = size - 1; i >= 0; i--) {
        if (priority >= priorities[i]) break; // encontro su lugar
        // El elemento actual tiene menor prioridad, lo corremos a la derecha
        elements[i + 1] = elements[i];
        priorities[i + 1] = priorities[i];
        insertIndex = i;
    }

    elements[insertIndex] = element;
    priorities[insertIndex] = priority;
    size++;
}
Ejemplo paso a paso

Array actual: [A(1), B(3)]. Insertamos C con prioridad 2.

i=1: prioridad 2 < B(3)? Si → corremos B a la derecha. insertIndex = 1.

i=0: prioridad 2 < A(1)? No → break.

Resultado: [A(1), C(2), B(3)] ✓

SimpleLinkedPriorityQueue — insercion en nodos

La version enlazada hace lo mismo pero navegando nodos. Tiene 3 casos especiales:

@Override
public void enqueue(E element, int priority) {
    PriorityLinkedNode<E> newNode = new PriorityLinkedNode<>(element, priority);

    if (isEmpty()) {
        first = newNode; last = newNode; // caso 1: lista vacia
    } else if (priority < first.priority) {
        newNode.next = first; first.prev = newNode; first = newNode; // caso 2: va al frente
    } else {
        // caso 3: busca su posicion desde el final
        PriorityLinkedNode<E> current = last;
        while (current.prev != null && priority < current.priority) {
            current = current.prev;
        }
        // inserta newNode DESPUES de current
        newNode.next = current.next;
        newNode.prev = current;
        if (current.next != null) current.next.prev = newNode;
        else last = newNode;
        current.next = newNode;
    }
    size++;
}

// Uso en AuthService: la clave es String (username), el valor es User
SimpleDictionary<String, User> users = new SimpleLinkedDictionary<>();

SimpleLinkedDictionary — insercion al frente

Esta implementacion usa una lista simplemente enlazada (solo next, sin prev). Los nuevos pares se insertan al frente de la lista. La logica de put primero busca si la clave ya existe para actualizar:

@Override
public V put(K key, V value) {
    // Busca si la clave ya existe → si si, actualiza y devuelve el valor viejo
    SimpleDictionaryNode<K, V> current = first;
    while (current != null) {
        if (current.key.equals(key)) {
            V previous = current.value;
            current.value = value;   // actualiza en el lugar
            return previous;
        }
        current = current.next;
    }
    // No existia → inserta al frente (O(1))
    SimpleDictionaryNode<K, V> newNode = new SimpleDictionaryNode<>(key, value);
    newNode.next = first;
    first = newNode;
    size++;
    return null;
}

Enum con dos valores: ALTO(1) y BAJO(2). El numero entre parentesis es el valor numerico que se le pasa a la PriorityQueue — 1 = mas urgente.

El nucleo. Tiene 4 colas de prioridad: inbox y una por pestana. Maneja todo el flujo de emails.

Flujo de un email

composeLogic() — llega un email
system.receiveEmail(email) → se encola en inbox con su prioridad numerica
inboxLogic() — el usuario ve su bandeja
Muestra todos los emails ordenados por prioridad via listInbox()

readTopTabLogic() — el usuario lee
readTopEmail(tab) hace dequeue de la pestana — el email queda "leido" y se elimina

El metodo mas complejo: listQueue()

Para mostrar los emails sin sacarlos permanentemente de la cola, usamos un patron de vaciar en temporal, mostrar, reponer:

private Email[] listQueue(SimplePriorityQueue<Email> queue) {
    int n = queue.size();
    Email[] result = new Email[n];
    SimplePriorityQueue<Email> temp = new SimpleLinkedPriorityQueue<>();

    // 1. Vaciar la cola original en result[] y en temp
    for (int i = 0; i < n; i++) {
        Email email = queue.dequeue();
        result[i] = email;
        temp.enqueue(email, email.getPriority().getNumericValue());
    }

    // 2. Restaurar la cola original desde temp
    while (!temp.isEmpty()) {
        Email email = temp.dequeue();
        queue.enqueue(email, email.getPriority().getNumericValue());
    }

    return result; // la cola quedo igual que antes
}
Por que no hay un iterador?

Las colas de prioridad no tienen metodo de recorrido sin destruir — solo saben hacer dequeue. Para "ver" los elementos sin modificar la estructura, la unica opcion es vaciarla temporalmente. Es un trade-off del TDA.

// En User.java
public void registerFailedAttempt() {
    failedAttempts++;

Por que Dictionary y no una Lista?

Acceso semantico por clave

Con una lista tendriamos que recorrer todos los usuarios para encontrar uno por username. Con un Dictionary, hacemos users.get("juan") directamente. El codigo es mas claro y expresa mejor la intencion: "dame el usuario cuyo nombre es 'juan'".

Generics en Java Concepto avanzado

Los generics permiten que una clase funcione con cualquier tipo de dato sin perder seguridad de tipos. En lugar de hardcodear String o Integer, usamos un parametro de tipo (<E>).

// SIN generics — solo funciona con String, y necesita casteos
public class StringList {
    Object[] elements;
    public String get(int i) { return (String) elements[i]; } // casteo riesgoso
}

// CON generics — funciona con CUALQUIER tipo, sin casteos en el uso
public class SimpleArrayList<E> {
    E[] elements;
    public E get(int i) { return elements[i]; } // tipo seguro
}

// Mismo codigo, distintos tipos — el compilador lo verifica
SimpleArrayList<String> strings = new SimpleArrayList<>();
SimpleArrayList<Integer> numbers = new SimpleArrayList<>();

El casteo unchecked: (E[]) new Object[]

En Java no se puede hacer new E[4] directamente por la forma en que funciona la JVM (borrado de tipos en runtime). La solucion es crear un Object[] y castearlo:

@SuppressWarnings("unchecked")
elements = (E[]) new Object[DEFAULT_CAPACITY];
// El compilador nos avisa del "unchecked cast", pero es seguro
// porque nosotros controlamos que solo entran elementos de tipo E
Por que @SuppressWarnings?

El compilador no puede verificar en tiempo de compilacion que el cast es seguro (por "type erasure"). La anotacion le dice: "yo se lo que estoy haciendo, callate la advertencia". Es una decision deliberada y documentada.

getNodeByIndex — optimizacion desde el extremo mas cercano

private LinkedNode<E> getNodeByIndex(int index) {
    validateIndex(index);
    LinkedNode<E> current;
    if (index < size / 2) {
        // El indice esta en la primera mitad → navega desde el frente
        current = first;
        for (int i = 0; i < index; i++) current = current.next;
    } else {
        // El indice esta en la segunda mitad → navega desde el final
        current = last;
        for (int i = size - 1; i > index; i--) current = current.prev;
    }
    return current;
}
Por que importa esto?

Sin esta optimizacion, buscar el ultimo elemento de una lista de 1000 requiere recorrer los 1000 nodos desde el frente. Con esta optimizacion, arranca desde el final y llega en 0 pasos. En el peor caso el recorrido es de n/2 en lugar de n.

removeAndReconnect — los 4 casos borde

Cuando eliminamos un nodo de una lista doblemente enlazada, hay 4 situaciones posibles que hay que manejar:

private void removeAndReconnect(LinkedNode<E> toRemove) {
    if (toRemove == first && toRemove == last) {
        // CASO 1: era el unico nodo → la lista queda vacia
        first = null; last = null;
    } else if (toRemove == first) {
        // CASO 2: era el primero → el siguiente se convierte en first
        first = toRemove.next;
        first.prev = null;
    } else if (toRemove == last) {
        // CASO 3: era el ultimo → el anterior se convierte en last
        last = toRemove.prev;
        last.next = null;
    } else {
        // CASO 4: estaba en el medio → conectamos anterior con siguiente
        toRemove.prev.next = toRemove.next;
        toRemove.next.prev = toRemove.prev;
    }
    size--;
}

add(int index, E element) — insercion en el medio

// Queremos insertar newNode ANTES de current (el nodo que estaba en ese indice)
newNode.prev = current.prev;  // 1. newNode conoce a su anterior
newNode.next = current;       // 2. newNode conoce a su siguiente

if (current.prev != null) {
    current.prev.next = newNode; // 3. el anterior apunta a newNode
} else {
    first = newNode; // si no habia anterior, newNode es el nuevo first
}
current.prev = newNode; // 4. current ahora apunta para atras a newNode
El orden importa CRITICO

Hay que asignar newNode.prev y newNode.next ANTES de modificar los nodos existentes. Si hicieramos current.prev = newNode primero, perderiamos la referencia al nodo anterior real y no podriamos completar la insercion.

Resize dinamico Concepto avanzado

Todas las implementaciones basadas en arreglos empiezan con capacidad 4 y se duplican automaticamente cuando se llenan.

El patron validateSize → resize

// Antes de cualquier insercion:
private void validateSize(int newSize) {
    if (newSize > elements.length) resize(); // solo redimensiona si es necesario
}

// En add():
validateSize(size + 1); // "necesito size+1 posiciones"
elements[size] = element;
size++;

Framework Exercise Patron de diseño

Cada "ejercicio" del menu principal es una clase que hereda de Exercise. Este es el patron Template Method: la clase base define el flujo general, las subclases implementan los detalles.

Exercise.java — la clase abstracta

public abstract class Exercise {
    protected boolean running = true;
    protected Scanner scanner;

    public void run() {
        while (running) {
            exerciseLogic(); // llama al metodo abstracto — polimorfismo
        }
        running = true; // resetea para la proxima vez que se use
    }

    protected abstract void exerciseLogic(); // cada subclase implementa su logica
}

Sistema de fases con currentPhase

Cada Exercise usa un int currentPhase como maquina de estados. En cada iteracion del loop, se ejecuta la fase actual:

// En ListExercise.java
private int currentPhase = 0;

@Override
protected void exerciseLogic() {
    switch (currentPhase) {
        case 0: menuLogic();              break; // menu principal
        case 1: addLogic();               break; // agregar elemento
        case 2: removeByIndexLogic();    break; // eliminar por indice
        case 3: removeByReferenceLogic(); break; // eliminar por valor
        case 4: clearLogic();            break; // limpiar lista
    }
    // Cada metodo modifica currentPhase para ir a la siguiente fase
    // running = false vuelve al menu principal del programa
}
Por que este diseño?

El Scanner se comparte entre todos los ejercicios — se crea UNA sola vez en MainProgram y se pasa por constructor. Esto evita crear multiples lectores del mismo stream, lo que causaria comportamientos inesperados. Ademas, cada ejercicio puede volver al menu principal simplemente poniendo running = false.

Flujo completo del programa

main() crea MainProgram y llama run()
Se crea el Scanner compartido. Empieza el loop principal.
selectExercise() muestra el menu y asigna exercise
El usuario elige un numero (1-9). Se instancia el Exercise correspondiente pasandole el Scanner.
exercise.run() ejecuta el loop interno
Llama a exerciseLogic() en loop hasta que running sea false (el usuario escribe "mm").
Vuelve al loop de MainProgram
Se vuelve a mostrar el menu principal. El ciclo se repite hasta elegir opcion 0.
